# Reading Helper

Телеграм-бот и Mini App, которые держат ритм чтения: что читаешь, сколько прочитал
и не выпал ли из графика. Работает целиком на [Telegram Serverless](https://core.telegram.org/bots/serverless) —
своего сервера нет, базы снаружи нет, платить не за что.

```
📄 кинул PDF       → книга добавлена, число страниц определено из файла
🔢 написал 147     → отметил, что ты на 147-й странице
➕ написал +20     → прочитал 20 страниц от последней отметки
⏱ написал 147 25м → плюс время, отсюда берётся скорость чтения
```

В ответ приходит то, что реально двигает к следующей сессии: где книга, взят ли
дневной минимум, как идёт неделя и когда книга закончится при текущем темпе.

## Что внутри

| | |
|---|---|
| **Цель** | недельная квота (чтобы занятый вторник можно было нагнать в субботу) плюс маленький дневной минимум (чтобы не выпадать совсем) |
| **Книги** | PDF хранится в Телеграме — бот помнит `file_id` и может прислать книгу обратно на любое устройство |
| **Страницы** | вытаскиваются прямо из PDF; если файл не даёт их узнать, бот честно спрашивает, а не выдумывает |
| **Напоминание** | вечером, и только если за день ноль страниц |
| **Дайджест** | по понедельникам: неделя, сравнение с прошлой, месяц одной строкой |
| **Карантин** | книга без движения 14 дней → «дочитываем или в архив?» |
| **Контракт** | `/commit` — обязательство на 30 дней, бот считает процент соблюдения |
| **Год** | счётчик «N книг из M» и карточка при закрытии каждой книги |
| **Дашборд** | Mini App с графиками по дням и неделям, полкой и настройками |

## Запуск

Нужен Node 22+ и бот от [@BotFather](https://t.me/BotFather).

**1. Включить Serverless у бота.** BotFather → твой бот → Serverless → включить,
затем там же **CLI Access** — оттуда берётся токен вида `app<id>:<secret>`.

**2. Установить зависимости и залогиниться:**

```bash
npm install
npx tgcloud login          # вставить токен из BotFather
```

**3. Выложить код и создать таблицы:**

```bash
npm run deploy             # tgcloud push — код + Mini App
npx tgcloud migrate        # применить tgcloud/schema.js к базе
```

`push` печатает адрес Mini App вида `https://app123456.tgcloud.ai/`.

**4. Подключить дашборд.** Вписать этот адрес в `MINIAPP_URL` в
[`tgcloud/lib/config.js`](tgcloud/lib/config.js) и выложить снова (`npm run deploy`).
Тогда заработает `/app`. Заодно в BotFather можно повесить его на кнопку меню:
Bot Settings → Menu Button.

**5. Включить напоминания.** У платформы нет своего планировщика, поэтому часами
работает GitHub Actions: workflow [`.github/workflows/tick.yml`](.github/workflows/tick.yml)
раз в 15 минут вызывает `npx tgcloud run lib/tick`, а сам код при этом исполняется
на инфраструктуре Телеграма. Нужно только положить токен в секреты репозитория:

> Settings → Secrets and variables → Actions → New repository secret
> Имя `TGCLOUD_TOKEN`, значение — тот же токен из BotFather → Serverless → CLI Access.

Без этого шага бот работает полностью, просто молчит по вечерам.

Дальше — `/start` боту.

**Про GitHub-крон:** запуск по расписанию бывает с задержкой до 10–15 минут
(поэтому у напоминания есть окно опоздания в 90 минут), а в репозитории без
активности 60 дней GitHub выключает расписание сам.

## Команды

```
147 · +20 · 100-140 · 147 25м · 30 мин    отметить прогресс
/undo            отменить последнюю запись
/books           полка, переключение активной книги
/add Название    бумажная книга без файла
/pages 420       сколько всего страниц
/file            прислать PDF обратно
/finish /drop    дочитал / бросаю
/stats /week     сводка и неделя
/goal /min /year цели
/commit          контракт на 30 дней
/quote 42 текст  сохранить цитату · /quotes
/remind 21:00    напоминание (/remind off — выключить)
/tz +3           часовой пояс: от него зависят «сегодня» и «эта неделя»
/app             дашборд
```

## Как устроено

```
tgcloud/              всё, что исполняется на платформе
├── schema.js         таблицы: users, books, sessions, quotes, contracts
├── handlers/         message.js и callback_query.js — вся маршрутизация
├── endpoints/        POST /api/* для Mini App
└── lib/
    ├── parse.js      разбор «147», «+20», «с 100 до 140», «147 25м»
    ├── pdf.js        число страниц прямо из байтов PDF
    ├── inflate.js    свой DEFLATE: без него сжатые PDF не читаются
    ├── time.js       локальные дни и недели пользователя
    ├── format.js     прогресс-бары, спарклайны, склонения
    ├── view.js       тексты всех сообщений
    ├── progress.js   сессии, темп, недельная сводка
    ├── books.js      полка, карантин, статистика по книге
    ├── goals.js      контракт и годовая цель
    ├── app.js        флоу, общие для сообщений и кнопок
    └── tick.js       планировщик (его зовёт GitHub Actions)
miniapp/              Mini App: обычный HTML/CSS/JS, сборка не нужна
test/                 юнит-тесты и сквозные тесты флоу
docs/DESIGN.md        почему всё устроено именно так
```

Подробности решений — в [docs/DESIGN.md](docs/DESIGN.md), справочник по платформе —
в [docs/tgcloud-sdk.md](docs/tgcloud-sdk.md) и [AGENTS.md](AGENTS.md).

## Разработка

```bash
npm test                     # 100+ тестов, включая сквозные флоу бота
npm run status               # что изменилось локально против облака
npx tgcloud run handlers/message '{ "chat": {"id": 1}, "from": {"id": 1}, "text": "147" }'
npm run check:pdfs           # детектор страниц против настоящих книг (нужен poppler)
```

Тесты гоняют **настоящие** хендлеры: `test/sdk-double/` — это дубль платформенного
`sdk` (база на `node:sqlite`, Bot API записывает вызовы вместо отправки). Он
подключён как `file:`-зависимость, поэтому `import { db } from 'sdk'` в тестах
разрешается в дубль, а на платформе — в настоящий SDK. В деплой он не попадает:
`tgcloud push` выкладывает только `tgcloud/**.js` и папку Mini App.
